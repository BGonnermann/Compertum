## Limits and privacy

Recent local agent records are an observed local format, not a guaranteed permanent integration contract.
The official [Codex App Server reference](https://developers.openai.com/codex/app-server) describes typed lifecycle events.
This implementation reads existing local activity records. It does not attach to, resume, or restart another chat or server.
No prompt, reasoning, raw command, account value, tool output, credential store, or environment value is served.

Discovery inspects at most 128 recent headers within four MiB, over seven dated folders.
The reader retains at most 24 project sessions, reads at most 512 KiB per file and two MiB per poll,
and limits each JSON line to 256 KiB. It marks incomplete or omitted history explicitly.
Native sampling has a 0.75-second target, at most 128 candidate processes, and no elevation.
Working signals expire after 90 seconds. Reported running jobs expire after eight seconds without a heartbeat.
The server permits at most four simultaneous requests, so a document read does not block current activity.
The Hub keeps no transcript copy and writes no runtime database or account record.

The separate manual wrapper retains at most 64 bounded job receipts outside the repository.
Its process identity and heartbeat must both be current before the Hub shows Running.
Stopped, failed, and completed receipts remain preserved. The wrapper does not bypass the original program's limits.

Initial free host memory was 41.40 GiB. A later check found 34.25 GiB, which remained safe for bounded browser checks.
No new package, interpreter, browser, service, scheduled task, model process, operating gate, or account call was introduced.
Existing unrelated M5 work and saved failure history remain separate from this change.

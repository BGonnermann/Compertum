Primary sources checked11October2026: [positions](https://docs.alpaca.markets/us/reference/getallopenpositions), [orders](https://docs.alpaca.markets/us/reference/getallorders-1), [official model fields](https://alpaca.markets/sdks/python/api_reference/trading/models.html), [SDK request fields](https://alpaca.markets/sdks/python/api_reference/trading/requests.html). Positions is an unfiltered GET/v2/positions list. Orders supports status, limit up to500, ascending/descending submission order, nesting and order-ID cursors; ID cursors cannot mix with timestamp filters. SDK request fields lag the documented ID cursors. Time filters concern order submission, not recent fills or economic activity. Source confidence is documented contract only; no authenticated behavior verified.

Chosen bounded request profile: POSITIONS has no parameters. ORDERS is GET/v2/orders with exact parameters status=all, direction=asc, nested=false, limit an integer1..25, and optional nonzeroUUID after_order_id. No symbol/side/asset/time filtering. A bundle always starts without a cursor and scans the complete bounded listing from the beginning; continuation must use the preceding page's last order ID and the same limit. Up to8pages; final page must be shorter than the limit. This avoids timestamp-only continuation dropping equal-time orders. The cursor is submission-list position, never fill coverage. The25/8limits are conservative local fixture limits beneath the existing64KiB response bound; saturation remains blocked, no automatic expansion.

Parsing: preserve exact raw bytes and every row index/hash. Valid rows receive compact normalized identity/quantity/status fields. Malformed or unsupported row shapes receive explicit deficiencies, retain raw/index/hash, and cannot imply a clean account. Reject malformed top-level JSON and wrong account/origin using the existing contract. Duplicate/conflicting positions, order IDs or client IDs are deficiencies. Nested/foreign/short/fractional/unsupported activity stays visible. An individual cancel204 remains only request acknowledgement.

Bundle interface: build_portfolio_bundle(*, account, positions, orders:tuple, clock, calendar, as_of) -> PaperPortfolioBundle. Inputs are immutable PaperResponse records or None for missing evidence; orders is a bounded tuple. Validate compatible account/origin/alias, expected operations, chronological request/response/as_of times, account/position/order evidence at most30seconds old and clock evidence at most5seconds old. Bind raw/request/response hashes and ordering. Distinguish complete successful fixture-list shape from missing/error/truncated/unsupported/conflicting evidence. No caller complete/owned flags. Separate calls are not atomic. Account binding, system ownership, fill-event coverage, ledger/cash reconciliation, pinned-calendar agreement, quote/liquidity/eligibility/entitlement and native authority remain UNVERIFIED. Account cash remains distinct from buying power. Never emit real flat, risk-admitted, armed or transport-authorized state.

# Offline paper message contracts

11 October 2026. Design for the next independent M5 engineering increment under the owner's autonomous roadmap instruction. Primary implements; one bounded reviewer; no commits or publication. Existing explicit no-routine-approval direction controls execution of these reversible local decisions. M3 native campaign verification remains separately RAM-blocked.

Purpose: make paper API message preparation and fixture interpretation inspectable before any account access exists. This component cannot grant authority, dispatch a request, infer actual holdings, or establish M5 acceptance.

Chosen design: two pure standard-library modules, immutable canonical request records and retained raw response bytes. Reuse canonical encoding and ContractError. Keep existing DETERMINISTIC_FAKE schemas/driver/fixture clock unchanged. An SDK client is deferred because it creates transport capability and new integration dependencies. Relabeling fake records is rejected because their observations are invented.

Request contract: exact origin https://paper-api.alpaca.markets; nonzero UUID account/request IDs; bounded local alias; timezone-aware creation time; fixed method/path per ACCOUNT, CLOCK, CALENDAR, ORDER_BY_ID, ORDER_BY_CLIENT_ID, SUBMIT_ORDER and CANCEL_ORDER. Calendar ranges at most31days. Submit body permits only whole-share market/day or limit/day, extended_hours=false, explicit stable cmp- client ID. No arbitrary headers, URLs, redirects, bulk actions, replacement or credential fields. These shape restrictions do not perform risk or authorization checks.

Response contract: bind exact request digest, origin, account context and receipt time; retain bounded raw bytes plus SHA256. Reject duplicate JSON keys, non-finite/nonnumeric financial strings, malformed success shapes, mismatched account/order/client IDs, inconsistent quantities/status and redirect evidence. Parse v2 account, clock, legacy calendar and stock order fixtures; retain error/timeout outcomes as unconfirmed. A cancel204 is only request acceptance; a lookup404 is not evidence an earlier POST failed. No automatic retry. Preserve late response timing explicitly.

All records state PAPER_WIRE_FIXTURE, transport_authorized=false and financial_accepted=false. Actual credential/account binding remains UNVERIFIED. An inert record is not a private execution capability. domain.py paper capabilities and all CLI/owner routes stay unavailable. Response/request bytes each bounded64KiB; metadata bounded64KiB. Depth32 and calendar31days are local defensive parser choices, not provider entitlements. No network/env/credential/filesystem access in these modules.

Acceptance: adversarial endpoint/path/account/request/body tests; exact raw-byte retention and reproducible canonical digests; clock/DST/early-close fixtures; order/quantity and cancellation/uncertainty cases; all existing paper capability denials remain. Source and installed-wheel identities/results must match. Maximum3 review/repair passes for this separate component. No M5 acceptance until the actual authorized independently audited walkthrough; M6 requires elapsed sessions.
